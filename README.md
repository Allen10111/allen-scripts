# Allen Scripts

A searchable Roblox script library with in-hub ON/OFF switches.

## Load

```lua
loadstring(game:HttpGet("https://raw.githubusercontent.com/Allen10111/allen-scripts/main/allen_scripts_hub.lua"))()
```

## Library

Black tabbed interface inspired by Ringta's visible GUI layout, with Allen Scripts branding. Choose a game from the selector, use the left sidebar to open feature pages, and search across the complete library by game or script name. Ink Game has Home, Red Light, Dalgona, Glass Bridge, Hide & Seek, Tug of War, Auto QTE and Movement pages. Each feature retains its own ON/OFF switch. The title bar supports dragging, minimizing, expanding and closing. No external UI library or Ringta script is executed.

All scripts start OFF. Individual script buttons are removed in the hub build. Press C to toggle the PC soft camera lock; its hub switch stays synchronized. Use the hub switches to control features, Right Shift to hide/show the hub, or AS to reopen it. Drag the title bar to move the window.

Game-specific controls are disabled in other games. Mingle and the scrapped auto-combat project are excluded.

The hub and bundled engines are readable, not obfuscated. Executor support is required; Funky Friday additionally requires Actor execution. Compatibility can change with game updates.

## Mobile

The mobile window is capped at 430 by 430 pixels and adapts to portrait and landscape screens. A game selector and Tabs drawer replace the desktop sidebar. Feature lists scroll vertically and switches have 44-pixel touch height. Safe-area and on-screen-keyboard changes are handled. Tap AS to reopen the window and drag the title bar to move it. Desktop and simulated portrait/landscape layouts, cross-game search and Dalgona page filtering were checked in-game; physical mobile touch testing of this UI revision is pending. The executor must still support each feature's required APIs.

## Untitled Boxing Game Auto Combat (Build R12)

One hub switch under Untitled Boxing Game / Combat. Uses the native MobileEvents bindables for light/heavy punches, ultimate attempts, block, dash and equip; it does not replay raw remotes or synthesize keys. Only targets the replicated CharacterData.Opponent while alive and out of cutscene/stun/menu states. Native match lock-on supplies facing; a reversible per-object GetMoveVector override feeds bounded approach/spacing/retreat/circling directions through the game own movement code. Floor/wall checks can stop movement. Reads style punch animation profiles and replicated stamina, guard, attack, dash and recovery state. Attempts at most one defensive dash per tracked attack and respects native action checks. All attack counts are requests, not server-confirmed hits. Style-specific specials, feint recognition and perfect defense are not guaranteed. Starts OFF and restores movement, lock-on and held defensive inputs on OFF/destroy. Pure decision tests and local mocked-state/native-bindable fixture passed; exact combat effectiveness requires live testing.

Combat validation: a 60-second partner test produced 50 native attack requests, four dash requests and three guard requests, with a maximum recorded controller step of 1.662 ms and no controller errors/disconnect. A subsequent 30-second run produced 19 attack requests and one dash request; the opponent replicated health reached zero. These counts are requests, not individual confirmed hits or a guarantee of winning. Stamina recovery now latches until a reserve returns (65%, or 80% at low health); the final reserve changes were checked in the mocked local fixture. Physical mobile execution, style-specific abilities and universal perfect defense remain unverified.

### R13 combat improvements

Guards ordinary light threats when guard energy permits; prioritizes fresh affordable dodges for heavier threats. Reads native style stamina costs and dash delay, checks movement/defense restrictions, and cancels unaccepted guard requests rather than leaving pending blocks. Starts heavy/ultimate attempts only in sufficiently long estimated recovery openings (or a heavy guard-break opportunity), rejects all offense against a dashing target, and avoids starting fresh punches during recognized windup or briefly after wakeup. Recovery movement stops at a safe spacing distance. Circling preserves its intended partial magnitude; blocked movement/dodge routes try bounded alternatives. Forced movement bypasses automation. OFF cleanup still restores the original input method and lock-on even if a native release endpoint errors.

Validation: 43 pure decision cases and an extended local fixture cover partial-speed movement, opposite-side dodge selection, forced-movement pass-through, stamina recovery, wakeup restraint, local guard confirmation and OFF cleanup. In a monitored 50-second live run against a different opponent, 31 attack requests produced 27 observed local attack animations, with five local guard confirmations and one local dash confirmation; maximum step time 1.491 ms and no controller errors. Sampled damage totals were about 52.6 taken / 46.4 dealt; these were not a controlled before/after comparison and do not establish a win-rate improvement. Confirmed counters describe native local animations/states, not server-confirmed hits or successful evasions. The final wakeup restraint and partial-initialization cleanup changes were checked in the fixture.

Final R13 verification: after reloading the published build, a further 40-second live window recorded 44 attack requests with 39 observed local attack animations, nine guard requests/confirmations, and four dash requests/confirmations. No guard requests timed out, no controller errors were reported, and the maximum controller step was 2.461 ms. Low-stamina retreat and recovery pauses were observed. Health declined from about 74.4 to 60.1 despite regeneration, so the run still included incoming damage. The controller remained ON under the existing hub switch after monitoring ended. Both generated scripts compiled successfully; physical mobile execution remains unverified.
